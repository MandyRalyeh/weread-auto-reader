专为**微信读书网页版（weread.qq.com）**打造的长期挂机刷时长油猴脚本（Tampermonkey UserScript）。

---

## 💡 为什么做这个项目？（写在前面）

作为一个经常需要在副屏挂机刷阅读时长和挑战的用户，我在挂《托尔金中洲传奇（套装全七册）》这套两百多万字的大部头时遇到了非常头疼的问题：

市面上的脚本要么只能以极慢的速度向下滚动，要么放在后台挂机时，浏览器会自动把它冻结降频，导致挂机 1 小时往往只记录了 20 分钟；更致命的是，好不容易挂了两三天读完全书，脚本直接卡死在最后一页的结语推荐卡片上，无法继续自动跑。

因此，这个项目的初衷非常纯粹：**做一个真正能做到“7×24小时无需人工干预、分秒不差统计物理时间、读完全书自动跳回第一章无限循环”的无感挂机助手。**

---

## ✨ 核心功能一览

* 🔄 **真·全书完“无限自动循环”**：挂机读完数百万字的全书后，自动检测完结并安全平滑地跳转回第 1 章正文，重新开始下一轮阅读。
* ⏱️ **绝对物理时钟计时**：基于真实的系统绝对时间戳差值计算，杜绝后台定时器漂移，挂了多久就统计多久，绝不缩水。
* 🛡️ **严格物理视口几何核验**：结合元素实际渲染尺寸与屏幕视口坐标，彻底根除因网页预渲染 DOM 导致的误判。
* 🎵 **Web Audio 活跃保活机制**：通过微量静音音频通道让浏览器判定标签页为高优先级媒体播放，合法绕过 Chromium 后台休眠与降频策略。
* 🔁 **自动重试与防内存泄漏保活**：遇到网络抖动“加载失败”自动点击重试；每隔 90 分钟自动整页刷新，防止浏览器单页长期运行内存泄漏。
* 🎨 **精美暗黑磨砂悬浮控制面板**：实时查看下次翻页倒计时、单轮翻页数、累计总页数、累计总时长和循环轮次。

## 🛠️ 我们踩过的“大坑”与技术实现原理 (War Stories)

在调试这个脚本的过程中，我们前前后后踩过不少坑，也推翻过好几个版本的方案。把这些经验分享出来，希望能给开发同类浏览器自动化插件的朋友提供一些参考：

### 1. 为什么“文字停滞比对”行不通？
* **最初的设想**：翻页后抓取页面上的正文字符，如果连续 4 次翻页页面文字完全一样，就代表翻到了最后一页。
* **踩坑真相**：大部头书籍（如托尔金七部曲）正文前有长达十几页的“总目录”、“英国版前言”、“序言”，中间还有全屏插图“中洲地图”。在这些页面上翻页时，文字很少甚至完全没有文字，脚本直接误以为读完了，疯狂触发重置！
* **最终解决**：彻底废弃纯文本猜测机制，全面转为监听底层 DOM 实体组件。

### 2. 翻一页就跳回第 1 章？排查“隐藏预加载 DOM”幽灵
* **出现的 Bug**：升级某一版后，脚本刚翻一页正文，就立马弹窗说“检测到全书读完”，直接跳回了封面，循环轮次在短短几分钟内从第 1 轮一路飙升到第 26 轮。
* **逆向源码真相**：我们逆向了微信读书的前端打包源码（`9.f252b488.js`），惊讶地发现微信读书为了末页加载顺畅，在网页刚打开时，就**预先把封底结语卡片渲染进了 DOM 树**（里面静态写着“读完了”），平常仅仅是用 Vue 的 `v-show` 给父容器加了 `display: none`。如果脚本仅仅用 `querySelector` 去搜“读完了”，不论在哪一页都会命中这个隐藏元素！
* **最终解决（三层物理几何防线）**：
  1. **开局安全缓冲**：每轮翻页少于 20 页时，绝不启动末页判断（两百万字不可能翻几页就读完）；
  2. **物理渲染核验**：不仅查节点，而且检查 `offsetParent !== null`，并计算 `getBoundingClientRect()`，要求渲染宽高等物理尺寸必须在屏幕可视视口范围内；
  3. **2.5 秒延时二次物理复核**：首次捕捉信号后暂停翻页，2.5 秒后二次复查，确认仍在末页才正式执行跳转。

### 3. 为什么放在后台挂机，时长总是对不上？
* **踩坑真相**：现代浏览器（Edge / Chrome）对后台标签页有极其严苛的节能机制（*Timer Throttling*）。一旦窗口被切到后台或被遮挡，原本设置的 1 秒定时器会被强制降频到几分钟才触发一次，挂机 1 小时往往只能记上十多分钟。
* **最终解决**：
  - **物理时间对齐**：放弃 `totalSeconds++` 的朴素累加，改用 `Date.now() - lastTick` 绝对毫秒时间戳换算，物理时间过了多久就统计多久；
  - **音频通道保活**：初始化一个极低增益的静音 `AudioContext` 振荡器。在 Chromium 内核规范中，处于音频播放状态的页面享受最高优先级调度，绝不降频。

### 4. 全书完后如何 100% 稳妥回到第一章？
* 微信读书属于单页应用（SPA），单纯改变 URL 有时不会重新渲染章节。
* **最终解决**：采用双重降级跳转策略：
  1. 首先模拟用户点击右侧悬浮栏的 `☰ 目录` 按钮，自动寻找目录顶部的第一章封面组件触发微信内部的原生路由切换；
  2. 若 3 秒后页面仍停留在末页，则降级为底层 URL 替换策略（`location.replace`），直接以第一章的绝对 Hash 地址重定向刷新。

## 🖥️ 单屏幕用户的摸鱼挂机建议

很多朋友并没有两块显示器，在单屏使用时推荐以下两种姿势，比直接“最小化”更加稳定：

* **姿势 1（最推荐）：独立小窗口 + 直接被其他软件遮挡**
  * 将微信读书标签页拖出来成为一个独立的浏览器小窗口（哪怕缩成巴掌大也行）。
  * **不要点击操作系统的最小化按钮（`_`）**，直接在前台打开你的 Word、IDE、浏览器或游戏，让微信读书窗口自然被覆盖在最底层即可。只要窗口没有被最小化，浏览器就会全速渲染并保活。
* **姿势 2：利用 Windows 虚拟桌面（Win + Tab）**
  * 按快捷键 `Win` + `Tab`，在屏幕顶部点击“新建桌面”。
  * 把微信读书窗口放在“桌面 2”全屏运行。
  * 按 `Ctrl` + `Win` + `←` 切回“桌面 1”正常办公或娱乐，两不耽误，彻底眼不见心不烦！

## 🚀 安装与使用教程

1. **安装脚本管理器**：
   * 在 Chrome / Edge 扩展商店搜索并安装 [Tampermonkey (油猴)](https://www.tampermonkey.net/)。
2. **导入本脚本**：
   * 点击浏览器右上角油猴图标 -> 选择 **“添加新脚本”**；
   * 将本仓库中的 [`weread_auto_reader.user.js`](weread_auto_reader.user.js) 完整代码复制粘贴进去，按 `Ctrl + S` 保存。
3. **开启自动挂机**：
   * 在浏览器中打开 [微信读书网页版](https://weread.qq.com/) 并进入任意书籍阅读界面；
   * 右下角会自动呼出半透明控制面板，代表自动翻页与计时已正式启动！
